# TASK.md 课题 Demo

四个可运行示例，使用 Python 3.8+ 标准库。`join` 和 `warning` 真实调用解压后的
PECJ 组件，`drift` 和 `continual` 包含独立实现的在线算法，无需安装 Torch、NumPy
或 SRTFD 训练依赖。课题覆盖与后续算法工作见源码中的 `docs/examples/TASK_DEMOS.md`。

这些新增算法是用于展示流程的轻量基线，不代表课题中的 PDA、ELBO/VI、EMA/MLP
双模推断或 SRTFD 神经网络实现。所有输入均为带评测真值的合成数据。

## 运行

在 sageTSDB 根目录：

```bash
bash scripts/demo/run_task_demos.sh \
  --component "$PWD/dist/sage-tsdb-pecj-component-0.2.0-linux-x86_64"
```

输出在 `examples/outputs/task_demos/`，每个 Demo 有单独的 CSV 和 `summary.json`。
也可以直接运行本目录中的脚本，适用于补充包和安装后的目录：

```bash
python3 run_demos.py --demo all \
  --component /path/to/sage-tsdb-pecj-component-0.2.0-linux-x86_64 \
  --output /tmp/task-demo-results --seed 2026

# 不依赖 PECJ 组件的两个 Demo
python3 run_demos.py --demo drift --output /tmp/drift-results
python3 run_demos.py --demo continual --output /tmp/continual-results
```

`--demo` 可选 `all`、`join`、`drift`、`continual`、`warning`。同一路径的同名输出会被覆盖。
`--component` 是解压目录，不是 `.tar.gz` 文件。完整组件可直接运行；thin 包仍需配置其运行库。
源码目录会自动寻找 `dist/` 中的 0.2.0 组件；安装后的示例会寻找所在前缀下的 `bin/`。

在源码根目录运行 `bash scripts/build/package_task_demos.sh`，可生成独立的
`dist/sage-tsdb-task-demos-0.2.0.tar.gz` 补充包及 SHA256 校验文件，无需重建原组件。

## Demo 1：窗口 Join 与迟到影响

同一批 S/R 事件，按事件时间划分 4 个左闭右开窗口，每窗分别等待 0、4、16 毫秒。
调用方按照模拟到达时间截取可见记录，再调用真实 `IAWJ`，并用独立的
`sum(count_S[key] * count_R[key])` 校验每次结果。事件日志包含边界外记录，调用前先过滤窗口。

- `events.csv`：完整输入，含 `timestamp_us`、`arrival_us`、窗口和流名称。
- `windows.csv`：完整真值、可见真值、真实 Join 数、缺失匹配数、相对误差和耗时。
- 每次调用的子目录：实际输入 `s.csv`/`r.csv`、`pecj.log` 和 `status.json`。

这里展示迟到造成的信息缺失和等待代价。当前 CLI 不接收独立到达时间，并在完整批次末尾
完成计算，因此此 Demo 不测量 PECJ 内部的早停补偿或后验精度。`aqp_estimate` 也不作为
PDA 精度证据。引擎耗时与包含进程启动/动态库加载的 CLI 墙钟耗时分别记录。

## Demo 2：工况漂移与自适应聚类

生成“缓慢漂移 → 工况突变 → 旧工况回归”的二维流，插入孤立尖峰。
比较冻结中心与在线 EMA 微簇中心；连续 10 个紧凑的新颖样本形成新簇，保留旧工况 ID。
最多保留 4 个簇，超额时淘汰最久未使用的簇。每个点先预测再更新，更新不读取真值标签。

`predictions.csv` 记录每点分数、告警、更新前簇 ID 和新建簇事件；汇总报告
precision、recall 和误报率。工况切换期间的告警也计入误报，不从结果中剔除。
无标签算法无法保证区分持续故障与新工况，持续异常可能被吸收为正常簇。

## Demo 3：稀缺标签、核心集与增量诊断

初始仅有正常类和旧故障类；阶段一新增另一故障、旧故障缺席；阶段二旧故障少量回归。
在线阶段随机揭示约 20% 标签，其余样本只在距离与类间间隔均通过门限时使用伪标签。
先预测并计分，再接收标签和更新。置信度是启发式间隔分数，并非校准概率。

比较三个模型：冻结类中心、全局最近 36 样本 FIFO、每类最多 12 样本的均衡核心集。
核心集按特征空间最远点覆盖选择代表，每次从记忆样本重新计算类中心。这是原型级回放，
不含神经网络训练。三种模型总记忆上限均为 36，均衡模型在类别不足时有空闲配额。

`predictions.csv` 记录真值、可见标签、更新前预测、更新来源和记忆大小；汇总包含各阶段
独立留出集的逐类召回率、宏平均召回率、记忆类别分布和真实/伪标签更新次数。
留出样本不参与模型更新，评测会包含尚未学到的新故障类。

## Demo 4：Join 接入故障提前预警

温度 S 流与振动 R 流按采样 ID 对齐；模拟每秒一个窗口，共 24 窗。
真实 PECJ 返回匹配数，应用层按唯一 key 提取均值特征并校验匹配数一致。
完整匹配覆盖率不足 90% 的窗口停止诊断并中断连续告警计数。
前 8 个有效窗口用作已知正常标定，之后冻结均值/标准差，以标准化残差连续超限进行预警。

由于当前 PECJ 只返回计数，特征配对、CSV 结果持久化均由 Python 完成，不是 PECJ 返回的
匹配明细或自动写表。此例只支持每流窗口内 key 唯一；多对多输入会被明确拒绝。

`diagnosis.csv` 记录覆盖率、数据质量门控、特征、分数、告警与决策时刻。
故障真值时刻只用于评测，不提供给检测器；提前量以窗口结束加等待预算的模拟决策时刻计算，
包括等待时间，不等同于实际设备部署的提前量。它不验证 CXL，也未连接达梦数据库。

## 已复现结果

使用现有 0.2.0 Linux x86_64 组件、`--seed 2026`：

| Demo | 本次结果 |
|---|---|
| Join | 12 次调用均匹配可见数据的独立真值；相对完整真值的平均误差依次为 42.8125%、31.25%、0% |
| 漂移检测 | 冻结中心误报率 33.19%，自适应中心 2.98%；两者对 10 个尖峰的召回率均为 100% |
| 增量诊断 | 新故障阶段后，冻结模型新类召回为 0，FIFO 旧类召回为 0，核心集模型三类召回均为 100% |
| 提前预警 | 模拟提前量 7.9 秒；拦截 1 个数据缺失窗口 |

这些结果只说明该合成场景能够演示相应机制，不构成真实工业数据、算法优越性或第三方考核结论。
改变随机种子可能改变数值；脚本不硬编码这些结果，也不要求优势必须成立才退出成功。
真实 Join 结果或输入计数不一致、后端降级、组件执行失败会返回非零退出码。

## 验证

本目录可独立运行 11 项测试；真实组件检查需要显式设置环境变量，否则会跳过 1 项：

```bash
PECJ_COMPONENT=/path/to/extracted/component \
  python3 -m unittest discover -s . -p 'test_*.py' -v
```

检查重点包括预测/标签先后顺序、评测集不参与训练、记忆上限和旧类保留、孤立尖峰隔离、
簇 ID 与容量、缺失窗口打断告警、多对多特征拒绝，以及真实 CLI 的 `[start,end)` 边界。
